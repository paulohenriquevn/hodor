## Exceção ao single-flip invariant (documentada)

Este release fecha DOIS milestones (M5 e M6). O `cycle-release § Single-flip invariant` prescreve um checkbox por release; aqui M5 e M6 co-shiparam porque foram empilhados em `develop` sem release intermediário do M5 (o usuário escolheu seguir do M5 READY_TO_MERGE direto para o M6). Flipar apenas um deixaria o outro `[ ]` para sempre — pior corrupção de rastreabilidade. Decisão: flipar AMBOS com audit separado (`roadmap-runs/M5-*.md` e `M6-*.md`), ambos apontando a v0.6.0/PR #6. Caminho estrito (um milestone por release) exigiria ter feito `/release` do M5 antes de iniciar o M6.
